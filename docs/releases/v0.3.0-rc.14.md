# v0.3.0-rc.14

This release candidate adds a toolbox image volume and per-cluster session
limits for debug sessions, typed admission recipes, typed platform hotfixes and
new typed node-maintenance actions. It also makes audit delivery independent
of the authorization path, unifies the REST error schema and requires a
concrete registered cluster for every session. The full list is in
[CHANGELOG.md](../../CHANGELOG.md#030-rc14---2026-10-21).

## Debug sessions

- `DebugSessionTemplate.spec.toolbox` mounts a digest-pinned OCI image
  read-only as an image volume into workload containers, the node debug
  container and the pod-copy debugger (#1505).
- `DebugSessionClusterBinding.spec.maxActiveSessionsPerCluster` limits the
  sessions of one binding per target cluster (#1522).
- kubectl-debug ephemeral and pod-copy templates accept a security context. The
  CRD rejects privileged settings that the template's `allowPrivileged` does
  not permit and root settings that its `requireNonRoot` does not permit;
  pod-copy contexts must not be privileged (#1511).
- A request without `bindingRef` uses the first binding that allows the
  requester (#1535).
- Typed admission recipes: `policy-audit` and `webhook-fail-open` are applied
  for an independently approved session and reverted at its end (#1506).
- Typed platform hotfixes: the `HotfixRecord` CRD and plan, apply, rollback,
  reconfirm and close stages (#1508, #1509, #1512, #1513, #1514).

## Node maintenance

New typed actions: `link-cycle` and `restart-autonegotiation` (#1510),
`service-restart` (#1519), `module-load` (#1520) and `sriov-reprovision`
(#1521). The SR-IOV proof covers emulated `igb` PFs in a nested guest only;
it does not cover real NICs.

## Sessions and API

- A session request for a cluster pattern or an unregistered cluster is
  rejected with `422`. The UI shows a cluster picker for pattern escalations
  (#1539).
- REST errors use one schema (`error`, `code`, `cid`, `details`). `join`,
  `leave` and `renew` return the updated DebugSession. The approval-token
  `404` keeps `valid: false` and adds the error fields (#1537).

## Audit

- AuditConfig reloads no longer block SubjectAccessReview answers. A failed
  reload keeps the running pipeline only for unchanged configs (#1533).
- Emit never writes synchronously on the authorization path (#1540).
- An unchanged resync keeps the pipeline. A replaced pipeline drains, and
  shared ingress settings come from the first AuditConfig by name (#1541).
- Webhook sinks support a Slack/Mattermost payload format (#1536).

## Upgrade guidance

1. Apply the CRDs server-side before the controller (`kubectl apply
   --server-side --force-conflicts`; Flux and Helm already do this). The
   `DebugSession`, `DebugPodTemplate` and `DebugSessionTemplate` CRDs exceed
   the 256 KiB limit of a client-side `kubectl apply`; `make install` and
   `make deploy` now apply server-side.
2. Review the upgrade notes in the changelog for the new optional fields,
   the RBAC needed by admission recipes and hotfixes, and the node-maintenance
   image that the new actions require.
3. Session requests for `*` or for unregistered clusters now fail with `422`.
   Clients must pick a concrete cluster, for example from `clusterOptions`.
4. Clients that parse REST error bodies or the `join`, `leave` and `renew`
   responses must accept the new shapes.
5. go-jose 4.1.6 rejects RSA JWKS keys larger than 4096 bits.
